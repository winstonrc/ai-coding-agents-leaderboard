Formula v1 methodology

A descriptive point-estimate index for comparing coding-agent outcomes.

Definition

Scorev1 = 100 (p / 0.50)wp (10 / (c / p))wc (40 / (m / p))wt

p is Pass@1, c is mean cost in dollars per attempt, and m is mean duration in minutes per attempt. The three nonnegative priorities are normalized to sum to one. The default priorities are 60% Pass@1, 30% cost per success, and 10% time per success.

The anchors describe an index value of 100: 50% Pass@1, $10 expected cost per success, and 40 minutes expected time per success. Anchors affect the displayed scale, not ordering.

What the priorities mean

The controls weight three outcomes, not three independent raw measurements. Cost per success is c / p; time per success is m / p. Expanding the formula gives:

Scorev1 ∝ p · c−wc · m−wt

Reliability therefore has an effective elasticity of one: failure affects the success rate, retry cost, and retry time. Increasing Pass@1 priority reduces the raw cost and time penalties; it does not increase reliability elasticity beyond one.

Interpretation limits

Formula v1 is a descriptive point-estimate index, not a calibrated utility function. It does not express uncertainty, the value of developer time, or the severity of a failed result.

Retry-adjusted cost and time assume comparable independent attempts and detectable success. Correlated or deterministic failures can make those estimates optimistic. Upstream exclusions can also produce slightly different task coverage between configurations; the leaderboard keeps those configurations rankable and displays their coverage.

Exceptional values

  • Pass@1 of zero receives a score of zero and infinite retry-adjusted cost and time. It remains in an unfiltered table but is omitted from the finite plot.
  • Nonpositive or nonfinite mean cost or duration is unpriced and excluded from scoring and Pareto calculations.
  • Equal scores remain tied. Configuration ID is only the deterministic ordering fallback.
  • The all-zero priority state is invalid. The interface retains the last valid priorities.

Pareto frontier

A configuration is point-estimate Pareto-efficient when no other rankable configuration has at least as high Pass@1, at most as much expected cost per success, and at most as much expected time per success—with at least one strict improvement. This is not statistical dominance.

The chart displays every finite selected configuration above the Pass@1 floor. The shared model filter limits both chart and table, and the Pareto frontier is recalculated over that selected set. The Pareto control filters only the table.

Version and data

Formula v1 is immutable. A future methodology must use a new formula module and version. The stable ?formula=v1 selector chooses this calculation; it does not pin or replay a historical dataset.

The site applies Formula v1 to the latest available published benchmark data from the pinned v1.1 aggregate feed. This independent project is not affiliated with or endorsed by the benchmark publisher. It keeps no data snapshots, so rankings are unavailable during an upstream outage.
